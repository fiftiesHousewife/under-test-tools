# This repo's backlog is plan/under-test-tools-backlog.yaml, synced to its issues by under-test's shared workflow after each push

**Decided by:** under-test-tools maintainers · **Status:** proposed

## Context and Problem Statement

Our other repos keep their work in a backlog file, synced to the repo's GitHub issues by one shared workflow. under-test-tools' work has been tracked only in under-test's backlog.

## Considered Options

* **A backlog file here, synced by `.github/workflows/sync-backlog.yml`, holding this repo's own work (its releases, its decisions); each new sub-command stays an item in under-test's backlog, where its skill is**  
  The same set-up as the other repos; this repo's housekeeping is visible beside its code, and nothing is tracked twice.
* **Move every sub-command's item here too**  
  All under-test-tools work in one place, but each item is then split from its skill's.
* **No backlog here**  
  Nothing to keep up, but this repo's own work has no home.

## Decision Outcome

Proposed: `plan/under-test-tools-backlog.yaml`, checked by `schema/backlog-seed.schema.json` (a copy of the shared schema), synced to this repo's issues after each push that changes it, with `docs/BACKLOG.md` regenerated by the workflow.

### Consequences

* The first push that changes the backlog file creates this repo's issues.
* The work-on-an-item skill works from it.
